# ESP32-S3 pin allocation, expander maps and I2C address map

Rev B: the four motor outputs now carry bidirectional DShot to the separate 4-in-1 ESC board (AM32) instead of driving brushed-motor MOSFET gates, and the IMU is the ICM-42688-P. Every other pin is unchanged from rev A.

Source data: `pin-allocation.csv` (single source of truth). Automated check: `python3 review/G1/calc/check_pins.py` → `pin-check-report.txt` (current result: **0 errors, 8 warnings**, all warnings are boot-sensitive pins listed below). It checks the table against datasheet facts typed into the script (pin numbers, reserved pins, strap pull directions, motor-pin rules) - it cannot check that those typed facts are right. Running it with `--module N16R8` shows the three errors that rule out octal-PSRAM modules.

Module facts come from the ESP32-S3-WROOM-1/1U datasheet v1.8 (2023-11-21), fetched 2026-10-04: <https://documentation.espressif.com/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf>. **The human must re-check every row against the datasheet revision of the modules actually purchased.**

## 1. GPIO budget

| Item | Count |
|---|---:|
| GPIOs brought out on WROOM-1 (Table 3-1) | 36 |
| Lost on octal-PSRAM variants (GPIO35-37) | 3 → only 33 on N16R8/N8R8 |
| Needed by this design | **35** |
| Spare on N8R2 | **1** (GPIO1) |

Needs: camera DVP 12, SPI 3 + 2 chip selects + 1 interrupt, I2C 2, ESC DShot 4, ELRS UART 2, USB 2, debug UART0 2, BOOT 1, expander/alert interrupt 1, LED data 1, buzzer 1, power KILL 1. Battery voltage comes from the INA226 (D-021). Everything slower is on the I2C expanders (section 3).

GPIO1 is spare (ADC1-capable). If more pins are needed later, the cheapest to free are GPIO43/44 (debug UART0 - USB Serial/JTAG remains).

**LED data (D-042):** bidirectional DShot uses all four RMT TX and RX channels, so the WS2812B data on GPIO45 is generated by SPI3 (MOSI only) through the GPIO matrix.

**Checks for G2:** (1) bidirectional DShot idles high once running, while the 100k pull-downs hold the lines low at boot - confirm AM32 accepts this; (2) SPI2 carries the ICM-42688-P at 8 kHz and the PMW3901 at 2 MHz with inter-write gaps - work out the bus-time budget.

Why the ESC outputs sit on GPIO2/21/38/47: none is a strapping, default-JTAG or eFuse-dependent pin, and each has a 100 kΩ pull-down so the DShot lines stay idle (no frames, motors stopped) while the chip is in reset or booting. DShot is generated by the RMT peripheral (the ESP-IDF documents an RMT DShot example); bidirectional DShot for RPM telemetry on ESP32-S3 is reported by the esp-fc project but is **UNCONFIRMED** here. **Confirm on the bench at G6 with props off** (scope each line through power-up and reset).

**U11 (address 0x21) - mostly inputs**

| Pin | Net | Dir | Notes |
|---|---|---|---|
| P0 | TOF_FWD_INT_N | in | VL53L5CX interrupt. |
| P1 | CHG_INT_N | in | BQ25887 /INT (open-drain) - charge status and faults are then read over I2C. |
| P2 | VBUS_DET | in | USB VBUS present (BQ25887 power-good output, or a VBUS divider - pin to confirm at G2); firmware will not arm while USB is connected. |
| P3 | PWR_BTN_INT_N | in | LTC2954 INT - user asked to power off; firmware lands, then KILL. |

| P7 | SPARE | - | Test pad. |

Both expanders' INT outputs and INA226 ALERT are open-drain and wired-OR onto EXP_INT_N (GPIO3).

## 4. I2C address map (7-bit), main bus at 400 kHz

| Address | Device | Notes |
|---|---|---|
| 0x20 | U10 TCA6408A | ADDR low |
| 0x21 | U11 TCA6408A | ADDR high |
| 0x29 → 0x31 | U15 VL53L1X down | All VL53L1X/VL53L5CX power up at **0x29**; firmware releases one XSHUT/LPn at a time and reassigns, every boot. |
| 0x29 → 0x32 | U16 VL53L1X left | |
| 0x29 → 0x33 | U17 VL53L1X right | |
| 0x29 → 0x34 | U18 VL53L1X rear | |
| 0x29 → 0x35 | U19 VL53L5CX forward | |
| 0x2C | U14 QMC5883P | Fixed address. |
| 0x30 | OV2640 SCCB | Fixed; new ToF addresses deliberately skip 0x30. |
| 0x40 | U9 INA226 | A0 = A1 = GND |
| 0x76 | U13 BMP390 | SDO to GND (must not float) |

No collisions after reassignment. If OV5640 replaced OV2640, its SCCB address 0x3C would still be free here.
